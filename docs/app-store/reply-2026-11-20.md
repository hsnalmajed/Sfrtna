Hello App Review team,

Thank you for checking again. You were right, and we found the cause.

The app itself never loaded our analytics, but two things outside our code still reached third-party domains from inside the app:

1. Our hosting provider (Cloudflare) was automatically adding its "Web Analytics" script (static.cloudflareinsights.com) to every page of sfrtna.com, including the pages shown in the app. We have turned this feature off for the whole website.
2. The Google sign-in script (accounts.google.com, which also reports to play.google.com) could load for a moment on the Account and "My map" pages before the app was detected. It no longer loads in the iPhone app; sign-in there is Sign in with Apple or an email code only.

We checked the result on the live site with the app's own user agent, page by page (home, destination guides, flight and hotel results, account, my map, privacy). The pages now contact no third-party script, frame, analytics or advertising domain, and set no tracking cookie. The only other hosts are image files (photos and country flags), which run no code. This check now runs automatically on sfrtna.com after every update, so we will know at once if anything like this appears again.

The iPhone app shows no cookie prompt, does not track users, and links no data with third parties; App Privacy states "Data Not Used to Track You". No new build is needed because the app loads these pages from our site, so build 51 already shows the corrected pages.

We would be grateful if you could review build 51 again.

If you still see any issue, we kindly ask you to share the details: the exact domain or domains contacted, the screen or steps where it happened, and the cookie name if a cookie is involved. With those details we can fix it at the root right away, instead of guessing.

Thank you,
